# 기존 코드 스타일 적용 지침

2026-10-14 사용자 지시: 기존 프로그래밍 규칙·함수명·작성 습관을 분석하고 최대한 유사하게 작성한다. 효율성 차이가 크면 더 나은 구현을 선택하되 기본은 사용자 코드 스타일이다.

## 적용 순서

1. 수정 파일과 가까운 기존 구현을 먼저 읽고 명명·배치·들여쓰기·주석을 따른다. 새 파일은 동일 역할의 기존 파일을 기준으로 한다.
2. Unreal 필수 규칙과 정확성·수명 안전성·명확한 성능 차이를 우선한다. 스타일 취향만으로 기존 코드를 재작성하지 않는다.
3. 예외가 필요하면 변경 이유와 비용/안전성 차이를 설명한다. 무관한 포맷 변경이나 기존 공개 함수 이름 변경을 함께 하지 않는다.

## 기존 코드에서 확인한 관례

- `DialogueSubsystem`, `PortraitSubsystem`, `DialogueNodeInfo`, `DialogueGraphEditor`, `DialogueEdGraphNode`를 기준으로 조사했다. 최근 AI가 추가한 BlockIdentity와 Tests는 사용자 스타일의 근거에서 제외했다.
- 클래스/구조체/enum의 U/F/E 접두사, 함수와 변수 PascalCase, bool의 b 접두사. Get/Set/Add/Remove/Update/Is 계열의 구체적인 동사형 이름을 사용한다. 출력 인자는 Out, 새 설정 인자는 New, 현재 상태는 Current를 사용한다.
- Id/ID/Guid 표기가 혼재한다. 기존 이름은 유지하고 새 이름은 관련 공개 계약과 일치시킨다. 기존 NodeGuid/PinId를 다른 식별자로 불필요하게 중복 도입하지 않는다.
- Allman 중괄호를 사용한다. Runtime은 탭이 많고 Editor는 탭/공백이 혼재하므로 파일의 인접 코드를 따른다. 새 Runtime 파일은 탭, 새 Editor 파일은 같은 역할 파일의 형식을 따른다. 한 줄 안에 여러 처리문이나 복잡한 조건문을 압축하지 않는다.
- 헤더는 pragma once, CoreMinimal 및 필요한 헤더, generated.h 마지막. 공개 함수와 private 상태를 구분하고 .cpp에 구현을 둔다. 단순 getter는 기존 파일처럼 inline도 허용한다.
- TArray/TMap 등 Unreal 컨테이너, const 참조 입력, UObject 공개 포인터 인자 관례를 따른다. 신규 소유 UPROPERTY는 TObjectPtr를 우선하며 게임 상태 원본을 불필요하게 복제하지 않는다.
- 함수 위에 동작을 설명하는 한국어 주석, 복잡한 처리에는 이유·오류 반환 의미·게임 확장 책임을 설명한다. pragma region은 일부 파일의 예외이므로 일괄 확대하지 않는다.
- nullptr/유효성/범위 검사를 먼저 하고 반환한다. 인접 코드의 `== false` 표현을 따른다. 초기화 누락, 무검사 배열 접근, 죽은 코드/불필요한 복사까지 따라 하지 않는다.
- 로그는 전용 카테고리와 `Class::Function : 이유` 형태를 따른다. 범용 진단 계약이 있는 경우 같은 정보를 게임 구독자에게 전달한다. 정상 흐름에 과도한 로그를 늘리지 않고 외부 전송은 게임 책임으로 둔다.
- 편집은 기존 Modify/알림/직렬화 흐름을 존중하되 Undo를 위해 변경 전에 Modify를 호출하는 등 올바른 UE 생명주기를 지킨다.

## 검토 기준

기능 검토 때 인접 코드와 명명·형식·주석 일관성을 함께 확인한다. 공개 API/기존 에셋 호환성은 스타일보다 우선한다. 성능을 이유로 다른 방식을 선택하면 추정과 측정 결과를 구분한다. 기존 파일의 줄바꿈을 대량 변환하지 않으며 새 파일은 프로젝트 LF 규칙을 따른다.
