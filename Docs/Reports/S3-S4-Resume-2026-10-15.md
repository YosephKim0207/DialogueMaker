## 이번 변경

`feature/dialogue-checkpoint-evidence`에서 실행 증거 기반을 구현했다. 새로운 CheckpointState는 스키마 2를 생성하며, 스키마 1 이전은 알 수 없는 과거를 완전한 증거로 만들지 않는다. 누적 열람과 현재 실행의 Line 통과/효과 성공을 분리한다. End 성공 정리는 해당 저장에 포함된 선택 occurrence만 제거한다. 완료 저장을 복원할 때 임시 선택을 되살리지 않는다.

효과 원장은 BlockRunId와 ChoiceId를 추가로 보관한다. 샘플 합본은 완전한 증거의 Block/Node/실행/선택을 대조하여 과거 실행의 지급 증거가 현재 실행에 섞이지 않도록 한다. 공개 사용법은 [사용자 안내서](../UserGuide.md#24-누적-열람과-실행별-저장-증거)에 있다. 자동 실행/저장 연결은 아직 구현 중이다.

## 검증

- Editor Build 성공: `Saved/AI/20261015_141152_bb60fe77/Build.log`.
- 자동화 2회 시도: `20261015_140855_c2fccc38`, `20261015_141010_895bb9a8`. UE가 최소 해상도 검사에서 종료해 테스트 보고서 없음. 실제 Windows 화면 조회는 508×948로 최소 너비 640 미달. 테스트 성공으로 처리하지 않는다.
- 신규 테스트: 스키마 이전/누적 이력/End 정리/실행별 통과·효과/다른 실행 원장 거부. 해상도 복구 후 재실행에서 통과했다.
- GUI/PIE, 패키징, 패키지 실행은 이번 변경에서 미실행.
- 해상도 복구 후 전체 DialogueKit 37개 성공, 실패 0개, 오류 로그 0건, StartupClean=true. 결과: `Saved/AI/20261015_142642_c7d18338/result.json`. 이전 시작 실패와 구분한다.
- 검증된 기능 브랜치를 Codex_Develop에 통합한다. 기능 브랜치는 보존하며 엔진 설정·모니터 설정을 임의 변경하지 않았다.
